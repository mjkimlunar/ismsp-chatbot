# ISMS-P 인증기준 안내 챗봇

ISMS-P 인증기준 101개 항목과 신청·심사 절차, 그리고 **개인정보 보호법** 조문을 **원문에 근거해서만** 안내하는 브라우저 RAG 챗봇입니다.
답변마다 근거가 된 항목번호와 원문 링크를 보여 주고, 자동 판정 결과를 함께 남깁니다.

- **배포 주소**: https://mjkimlunar.github.io/ismsp-chatbot/
- **기획 문서**: [PRD.md](PRD.md)
- **평가 세트·루브릭**: [eval/questions.json](eval/questions.json) · [eval/rubric.md](eval/rubric.md)

## 처음 오신 분께 — 실행 전에 확인할 조건

이 페이지는 **답을 대신 만들어 주지 않습니다.** 정적 페이지를 여러분 브라우저가 실행하고,
답변은 **여러분이 고른 엔진**이 만듭니다. 두 가지 경로가 있습니다.

### 가장 빠른 경로 — Gemini API (설치 불필요)

1. https://aistudio.google.com/apikey 에서 API 키 발급
2. 페이지 상단 **답변 엔진 → Gemini API** 선택 후 키 입력
3. 질문 입력

키는 **여러분 브라우저의 localStorage에만** 저장되며 어디로도 전송되지 않습니다.

### 강의 기본 경로 — 로컬 Ollama

1. Ollama 실행 (`ollama serve` 또는 Ollama 앱)
2. 모델 준비: `ollama pull qwen2.5:3b`
3. 배포 주소에서 호출하려면 **CORS 허용**이 필요합니다. 한 번만 설정하고 Ollama를 재시작하세요.

   ```bash
   # macOS
   launchctl setenv OLLAMA_ORIGINS "https://*.github.io"
   ```

   **Windows**: 작업 표시줄에서 Ollama를 종료합니다. 설정에서 **환경 변수**를 검색해
   **계정의 환경 변수 편집**을 열고 새 변수 `OLLAMA_ORIGINS`에 `https://*.github.io`를
   넣은 뒤 Ollama를 다시 시작합니다.

   ```bash
   # Linux (systemd)
   sudo systemctl set-environment OLLAMA_ORIGINS="https://*.github.io"
   ```

### 속도 개선 — IPEX-LLM (Intel 내장 GPU 가속)

Intel Core Ultra / Arc 내장 GPU가 있다면 **IPEX-LLM Ollama**를 쓰면 훨씬 빠릅니다.
기본 Ollama(CPU)에서 ~3 tok/s이던 속도가 **~21 tok/s (7배)**로 올라갑니다.

1. [IPEX-LLM Releases](https://github.com/ipex-llm/ipex-llm/releases)에서 `ollama-ipex-llm-*-win.zip` 다운로드 (약 108MB)
2. 압축을 풀고, 기존 Ollama를 종료한 뒤 CMD에서 실행:
   ```
   cd C:\압축해제경로
   start-ollama.bat
   ```
3. 새 CMD 창에서 `ollama run qwen2.5:3b`

기존 Ollama와 별도로 동작하며, 기존에 받아둔 모델을 그대로 씁니다.

> **참고**: IPEX-LLM 프로젝트(intel/ipex-llm)는 **2026-01-28에 아카이브**되어 더 이상 업데이트되지 않습니다.
> 마지막 빌드가 번들하는 Ollama는 **0.9.3**(2025-06 기준)이므로, 이후 출시된 모델(qwen3.5 등)의
> 모델 포맷을 인식하지 못합니다. `qwen2.5:3b` 등 기존 모델은 정상 동작하며 iGPU 가속 효과도 유효합니다.

## 이 챗봇이 답하는 것과 답하지 않는 것

**답합니다**
- 인증기준 각 항목이 무엇을 요구하는지 (`1.1.1`, `2.6.2` 처럼 번호로 물어도 됩니다)
- 주제별로 어떤 기준들이 있는지 (예: 접근통제, 개인정보 파기)
- 인증 신청·심사·사후관리·인증서·이의신청 절차 (고시 조문 근거)

**답하지 않습니다**
- 법률 자문, 특정 조직의 유권해석
- 인증 대상 여부·심사 통과 가능성·결함 여부 **판단**
- 인증기준을 **어떻게 이행하는지** — 그 해설은 KISA 안내서에 있고 이 챗봇의 자료에는 없습니다

마지막 항목은 기능을 덜 만든 게 아니라 **자료 범위에서 비롯된 경계**입니다. 아래 설계 결정을 보세요.

## 설계 결정 요약

### 1. 안내서를 코퍼스에서 뺐습니다 (라이선스)

| 자료 | 라이선스 | 코퍼스 |
| --- | --- | --- |
| 고시 별표 7 인증기준 + 본문 조문 | 고시 = 저작권법 제7조상 보호받지 못하는 저작물 | **포함** |
| KISA ISMS-P 인증기준/제도 안내서 | **공공누리 제4유형** (출처표시 + 상업적이용금지 + **변경금지**) | **제외** |

안내서를 청크로 쪼개 재배포하는 것은 변경금지에 저촉될 소지가 있습니다. 그래서 이행 해설을 포기하고
**원문이 무엇을 요구하는지**만 답하는 범위로 제품을 좁혔습니다.

### 2. 현행본을 확인하고 대조했습니다

- 현행 고시: 개인정보보호위원회고시 제2024-8호 / 과학기술정보통신부고시 제2024-30호, **2024. 7. 24. 시행**
- 검색엔진 상위에 노출되던 2023.11 자료를 그대로 썼다면 낡은 코퍼스가 됐을 것입니다.
- 현행 별표 7 PDF는 표 셀이 병합돼 텍스트 추출이 어긋나므로, 구조가 보존된 직전본에서 파싱한 뒤
  **101개 항목 전부가 현행본 안에 그대로 존재하는지 문자열로 대조**했습니다.
  ([scripts/parse_byl7.py](scripts/parse_byl7.py), [scripts/diff_byl7_items.py](scripts/diff_byl7_items.py))

### 3. 도메인에 맞춰 검색을 고쳤습니다

참조 구현을 그대로 쓰면 이 도메인에서 두 가지가 깨집니다.

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| `1.1.1` 같은 **항목번호로 검색이 안 됨** | BM25 토크나이저가 `.`을 구분자로 보아 `1.1.1` → `["1","1","1"]` → 1글자 필터로 전부 소멸 | 항목번호를 한 토큰으로 먼저 분리 (`SEARCH.keepItemNumbers`) |
| 근거가 **잘린 채** 모델에 들어감 | 청크 평균 270자(최대 1,052자) × 15개 ≈ 5,000~7,300 토큰 > 기본 컨텍스트 4,096 | 근거 개수 15 → **4** (벡터 3 + BM25 1) |
| 3B 모델이 **핵심 청크를 무시**하고 엉뚱한 청크를 인용 | 근거 8개에서 노이즈가 많아 관련도 높은 청크(80%)를 무시하고 낮은 청크(72%)를 선택 | 근거 4개로 축소 + ★ 마커로 1위 청크 강조 |

검색 설정은 [app/src/rag.ts](app/src/rag.ts)의 `SEARCH` 한 곳에 모아, 실험 때 값 하나씩만 바꿀 수 있게 했습니다.

## 실험 기록

실행 날짜가 아니라 **실험 이름 · 바꾼 변수 · 고정 질문 판정 · 관찰 · 결정**을 남깁니다.
지표 정의는 [eval/rubric.md](eval/rubric.md), 질문은 [eval/questions.json](eval/questions.json).

### E0 — 베이스라인 (참조 구현 설정 그대로)

세팅: 벡터 top-10 + BM25 top-5 (총 15), 약한 근거 임계 0.55, 기본 토크나이저

| 관찰 | 결과 |
| --- | --- |
| Q1 `1.1.1이 뭐야?` | 기대 근거 `IC-1.1.1`이 **top-3에 없음**. BM25 기여 **0개** |
| Q7 `내일 날씨 어때?` | 최고 유사도 **0.567 ≥ 0.55** → 약한 근거로 표시되지 않음 |
| 프롬프트 크기 | 근거 15개 ≈ 5,000~7,300 토큰 > 컨텍스트 4,096 → **근거 잘림** |

결정: 사용할 수 없는 상태. 검색 축에서 변수를 하나씩 바꾼다.

### E1 — 항목번호 토큰 보존 + 근거 개수 축소

세팅: `SEARCH.keepItemNumbers = true`, 벡터 5 + BM25 3 (총 8)

| 관찰 | 결과 |
| --- | --- |
| Q1 근거 | `IC-1.1.1` **포함됨** (BM25 경로로 진입, 벡터 7 · BM25 1) |
| 남은 문제 | 약한 근거 경고가 **벡터 최고 점수만** 보고 판정 → BM25가 정확히 찾아낸 질문에서 "근거가 약합니다"가 뜸 |

결정: 채택. 약한 근거 판정 방식은 다음 실험(E3)에서 다룬다.

### E1b — 실제 실행에서 드러난 결함 세 가지 (프롬프트·상태 축)

E1 설정으로 화면에서 돌려 보니 검색 밖에서 세 가지가 나왔다. 코드를 읽는 것만으로는 안 보이고,
실행해야 보이는 종류였다.

| 결함 | 증상 | 원인 | 조치 |
| --- | --- | --- | --- |
| **과잉 거부** | `1.1.1이 뭐야?`에 "해설은 없습니다"라며 거절. 근거에 `IC-1.1.1`이 있었는데도 | 거부 규칙을 "이행 방법을 묻는 질문은 답하지 말라"로 넓게 써서, 항목이 무엇인지 묻는 질문까지 잡힘 | 규칙을 **부분 단위**로 다시 씀 — 자료에 있는 내용은 답하고, 자료 밖인 부분에만 선을 긋는다 |
| **판정이 다른 답변을 덮어씀** | 95점이던 답변이 갑자기 0점으로 바뀌고, 평어가 앞 질문 내용을 말함 | 판정 결과를 `turns[length-1]`에 씀. 느린 로컬 판정이 끝났을 때 이미 다음 답변이 마지막 칸을 차지 | 말풍선에 **고유 id**를 부여하고 그 id로만 갱신 (스트리밍·피드백도 동일) |
| **새로고침하면 엔진 초기화** | Gemini로 쓰다가 새로고침하면 로컬로 돌아가 몇 분씩 기다리게 됨 | 엔진 선택이 상태로만 존재 | `localStorage`에 저장 |

수정 후 Q1 재실행:

> 인증기준 1.1.1은 '경영진의 참여' 항목이며 … 보고 및 의사결정 체계를 수립하여 운영하여야 합니다. **[IC-1.1.1]**
> 구체적인 이행 방법 해설은 제가 가진 자료에 없으므로 KISA 'ISMS-P 인증기준 안내서'를 확인하시기 바랍니다.

판정 **100점** (근거 충실성 100 · 환각 통제 100 · 출처 표시 100, gemini-3.5-flash).
원문은 답하고 이행 방법만 넘기는 경계가 의도대로 그어졌다.

## 3B 모델 RAG 튜닝 기록

qwen2.5:3b로 RAG를 운영하며 겪은 문제와 해결 과정입니다.

| 문제 | 증상 | 해결 |
| --- | --- | --- |
| **과도한 거부** | 근거에 답이 있는데도 "자료에 없습니다" | 질문을 먼저 배치 + few-shot 예시 추가 |
| **환각 (기관명 지어냄)** | 학습 데이터의 중국 기관명을 한국 맥락에 삽입 | 출력 후처리(`postcheck.ts`)로 출처에 없는 고유명사 경고 |
| **CJK 언어 이탈** | 긴 답변에서 중국어·일본어로 전환 반복 | 스트리밍 중 CJK 3자 누적 시 즉시 중단 |
| **두루뭉술한 답변** | "3개월 이내"를 "일정 기간"으로 뭉뚱그림 | 수치·기간 원문 인용 지시 + 프롬프트 간소화 |
| **자료 범위 밖 질문** | 유출 신고 기관을 추측으로 답변 | **개인정보 보호법 125개 조문 추가** → 환각 → 100점 |

핵심 교훈: **자료 커버리지 > 프롬프트 튜닝 > 모델 크기**. 같은 3B 모델이라도 관련 자료를 추가하면
프롬프트만 개선한 것보다 답변 품질이 극적으로 올라갑니다.

## 알려진 한계

- **로컬 judge는 독립 평가가 아닙니다.** 답변과 판정을 같은 모델이 수행하므로, 세밀한 사실 차이나 문맥 누락을
  거칠게 판정할 수 있습니다. 판정 엔진을 Gemini로 분리하면 더 정확한 점수를 얻을 수 있습니다.
- **양식·수수료·절차**는 고시 기준입니다. 신청서 양식은 이후 개정될 수 있으므로(2026년에 2.4v·2.5v 개정)
  챗봇은 최신본을 자료실에서 확인하라는 안내를 함께 냅니다.
- 인증기준 **이행 방법**은 답하지 않습니다. 위 설계 결정 1 참조.
- **3B 모델의 환각**을 프롬프트만으로 완전히 막기는 어렵습니다. 출력 후처리가 출처 없는 고유명사를 경고하지만,
  일반 명사 형태의 환각은 잡지 못합니다.
- **IPEX-LLM 아카이브**: Intel iGPU 가속에 쓰이는 IPEX-LLM이 2026-01에 개발 중단되어, 번들 Ollama(0.9.3)가
  최신 모델 포맷(qwen3.5 등)을 지원하지 못합니다. NVIDIA GPU가 있으면 공식 Ollama가 CUDA를 자동 인식하므로
  이 제약 없이 최신 모델을 쓸 수 있습니다.
